# Рабочее окружение

Dotfiles для macOS в стиле Ayu Dark: Ghostty, Nushell/zsh, Herdr/tmux,
AeroSpace/Rift, Neovim, Yazi, LazyGit и Pi.

## Установка

Нужны Xcode Command Line Tools, Homebrew и Go 1.26+. Checkout — `~/dots`.

```sh
./install
make test                          # Go race/vet, Node и shell-контракты
./scripts/build-go-tools.sh         # пересобрать собственные утилиты
```

Пакеты — [Brewfile](Brewfile), ссылки и шаги установки — [steps/](steps/),
настройки — [config/](config/), свои CLI — [tools/dots/](tools/dots/).
Выборочная установка: `./install -c steps/pi.yml`.
Откат: `./uninstall --dry-run`, затем `./uninstall`; без `--packages`
Homebrew-пакеты не удаляются. VPN устанавливается [отдельно](vpn/README.md).

## На каждый день

```sh
dots                               # меню
dots status --interactive          # состояние окружения
dots sessions open                 # сессии и проекты
dots-tools palette --help          # общая тема
km                               # VictoriaMetrics: c сервис, / метрика, s раздел
km --preview                     # синтетический UI без подключения
```

В меню: ↑↓ / Ctrl+N/P — выбор, ввод — поиск, Enter — открыть, Esc — назад.
Опасные действия требуют явного `yes`; пустой Enter не подтверждает.
Аргументы команд — в `--help`, Kubernetes-команды — в `kube-tools-help`.
`Option+A` открывает Tinycast; автозапуск включается в настройках приложения.

## Kubernetes

`dots-kube` — отдельный переносимый бинарник; нужны `kubectl`, kubeconfig и
его auth-плагины. `dots-tools kube` использует тот же код.

```sh
dots-kube setup                    # файл → context → namespace → подтверждение
dots-kube config                   # сохранённые подключения без секретов
dots-kube doctor                   # локальная диагностика
kpstage get pods
kpstage namespace                  # сменить только namespace
kpstage-logs api
kpstage-logs-multi                 # выбрать несколько подов
kpstage-rollout-restart            # выбрать workloads
kpprod-deploy-watch api
```

Окружения: dev/stage/preprod/prod. Мастер сохраняет привязки в
`~/.config/dots-kube/`, не переписывая исходные kubeconfig и обычный
`kubectl current-context`. Команды `kp…` закрепляют context/namespace только
для своего вызова. Изменения в prod требуют подтверждения; для скриптов
предусмотрен явный `KPROD_CONFIRMED=1`.

Логи: Space — пауза, `/` — поиск, Enter — детали, `m` — краткий вид.
По умолчанию видны полные записи; `logs-save` сохраняет исходный вывод.
`rollout-restart` перезапускает workloads, `pod-restart` — конкретные поды.
Релизы macOS/Linux собираются через `./scripts/build-kube-release.sh`.

### Метрики VictoriaMetrics / Prometheus

`dots-kube metrics` — read-only TUI: общий обзор **трафика, ошибок, задержек,
ресурсов и готовности**, затем детали и разбивка по сервисам/подам/workloads.
29 базовых запросов разделены на Обзор / HTTP / Ресурсы / Состояние.
Дополнительно: **HTTP-ручки** (явный топ-10), **PostgreSQL**, **Redis**,
**Пулы и другие БД**, **Очереди**,
**Вход и доступность**. Пустые «Свои», Runtime и исходящие вызовы скрыты из навигации. Проверенные источники
подключаются через приватные queries; без сбора раздел объясняет, чего не хватает.
Русские пояснения, понятные единицы и непрерывные линейные графики с разрывами
при отсутствии измерений. **Один `km`**: `c` — сервис, `/` — поиск по всем метрикам,
`Tab` — переключение фокуса между разделами и единственной таблицей, `s` — меню.
Каждый сервис/инстанс получает строку со значением и динамикой; название метрики
не повторяется в каждой строке. `↑↓` / `j/k` — выбор, `Enter` — график ряда, `b` — разбивка.
HTTP-методы выделены цветом, подробные описания перенесены в справку;
`f` — фильтр HTTP-ручек, `←→` — период, `?` — помощь. Смена сервиса сохраняет открытую
метрику, общие показатели явно отделены от сервисных.
Ноль, отсутствующие данные и устаревший снимок показываются раздельно. Перцентили
помечены `≈`, а выход за конечный bucket — `≥`, без ложного плато на границе.

```sh
dots-kube metrics init           # пустой приватный config 0600, без перезаписи
# Заполнить локальный файл по пути, который напечатал init; затем:
dots-kube metrics check          # без сети и вывода координат
km                              # всё внутри одного TUI; команды менять не нужно
km rps --json                   # необязательно: данные для скриптов, без TUI
dots-kube metrics --preview --scenario degraded  # синтетический UI, без кластера
```

Подключения живут **вне Git**: kubeconfig/context/namespace, endpoint, remote port,
service-фильтры и токены не вшиваются в исходники. TUI сам поднимает явный
`kubectl port-forward` на случайном loopback-порту и убирает его при выходе;
возможен и прямой HTTPS/локальный endpoint. `km`/`kma` — native command links:
работают в zsh/Nushell без загрузки alias-файла. Их привязки к профилям хранятся
в поле `shortcuts` приватного JSON, а не в shell/Git. `kube-metrics-watch` сохранён.

## Pi и прокси

```sh
./install -c steps/pi.yml
pi-proxy --set-sub                 # первичная настройка VLESS-подписки
pi-proxy --install-service         # фоновой запуск после входа в macOS
pi
pi-proxy --status
pi-proxy --uninstall-service       # убрать наблюдатель, оставить xray
pi-proxy --stop                    # убрать наблюдатель и остановить xray
```

`pi-proxy` управляет настоящим xray-core, а не реализует VLESS самостоятельно.
Фоновый LaunchAgent `local.dots.pi-proxy` запускается после входа пользователя
в macOS независимо от Pi/jg/других приложений. Он подхватывает уже работающий
xray без перезапуска и каждые 30 секунд проверяет реальную страну выхода и
OpenAI через текущий listener. Исправный маршрут не меняется ради скорости.
Одиночная ошибка не переключает сервер; после трёх последовательных сбоев
ищется замена. Подтверждённый RU-выход останавливается сразу. До четырёх
изолированных проверок параллельно ищут любой рабочий выход вне РФ.
РФ и неизвестная страна не считаются рабочими; прямого fallback нет.

Запуск `pi`, `jg` и Spotifast только проверяет локальную готовность (`--ensure`):
PID, listener и последняя успешная проверка не старше 90 секунд. Он не запускает,
не останавливает и не выбирает xray. Без готового маршрута приложение не стартует
напрямую. Ручной полный рейтинг: `pi-proxy --auto` (может прервать соединения).
Первоначальный подхват сохраняет текущие сессии, но реальный отказ маршрута и
последующее переключение могут оборвать TCP-запрос: бесшовного failover нет.
Логи наблюдателя: `~/.config/xray-pi/supervisor.log`.

Подписка и конфигурация — `~/.config/xray-pi/`. Системный VPN и proxy-настройки
не меняются. Shell-команды агента не наследуют proxy env; корпоративный MCP
обходит внешний туннель. Открытые Pi-сессии перезапускать не нужно;
для обновления функций в zsh/bash: `source ~/.config/shell/pi-proxy.sh`.

MCP заданы в `config/pi/mcp.json`: Peekaboo управляет Mac, Excalidraw создаёт
диаграммы. Проверка: `pi mcp list`; после применения настроек — `/reload`.
Peekaboo нужны разрешения macOS на запись экрана, Accessibility и синтетический
ввод: `peekaboo permissions status`. Excalidraw отправляет данные удалённому
серверу; секреты ему не передавать. Встроенного холста в Pi нет.

### Расширения Pi

Переносимые настройки лежат в `config/pi/` и восстанавливаются командой
`./install -c steps/pi.yml`. После установки перезапустите Pi: пакеты из
`settings.json` будут загружены автоматически; при первом запуске нужен интернет.

| В dots | Назначение |
| --- | --- |
| `config/pi/settings.json` | Пакеты, Powerline, отключение старого Ayu footer |
| `config/pi/web-search.json` | Бесплатный веб-поиск и чтение страниц |
| `config/pi/lens.json` | Глобальные настройки Lens → `~/.pi-lens/config.json` |
| `config/pi/extensions/powerline-footer/theme.json` | Цвета панели под Ayu |

Vibes (тематические фразы ожидания) отключены: `workingVibe: "off"`.

Lens проверяет код через локальные инструменты, форматирует в конце хода;
автоисправления линтеров и экспериментальная блокировка коммитов отключены.
Web Access использует Exa MCP без ключа, резервный DuckDuckGo и чтение HTTP/Jina;
PDF разбираются локально. Платные поисковые провайдеры, LLM-режим `answer`,
curator и анализ видео отключены. Бесплатные сервисы могут ограничивать частоту
запросов. API-ключи Exa/Jina не нужны: не добавляйте их в конфиг или окружение,
если хотите сохранить этот режим без оплаты. Стоимость основной модели Pi
этими настройками не меняется.

Установщик сохраняет дополнительные пакеты, локальные поля и авторизацию,
делает резервные копии изменяемых конфигов. Для Lens учитываются
`PI_LENS_CONFIG_PATH` и `PI_LENS_HOME`. Секреты, история, скачанные инструменты
и машинный `deviceId` в переносимые настройки не входят.

## Herdr

Обёртка сама собирает клиент с локальным патчем вкладок для установленной версии.
Первой сборке нужны Rust/Cargo; проверенный Zig при необходимости скачивается
в кеш. При ошибке используется стандартный или подходящий готовый клиент.

```sh
scripts/build-herdr-ui.sh          # повторить сборку без ожидания cooldown
HERDR_DOTS_NO_PATCH=1 herdr        # запустить исходный клиент
```

Логи и клиенты: `~/.local/share/dots/herdr/<version>/`.
Для нового UI переподключите клиент (Ctrl+A, D → `herdr`), не останавливая сервер.

## Поиск и тесты проектов

```sh
jg auth
jg "Где проверяется авторизация?" ./src
pytest-safe -- uv run pytest -n auto
```

Jevgrep отправляет выбранные исходники провайдеру: сужайте корень, сохраняйте
фильтры секретов. В shell-инструментах агента используйте `~/dots/scripts/jg`
для настроенного прокси. `pytest-safe` снижает приоритет процесса;
xdist по умолчанию использует два worker'а, явные настройки имеют приоритет.

## Приватные настройки

```sh
dots private init                 # создать отсутствующие шаблоны
dots private check                # проверить без вывода значений
```

| Путь | Содержимое |
| --- | --- |
| `~/.config/dots/private.zsh` | Личные алиасы, endpoints и пути; [пример](config/zsh/private.example.zsh) |
| `~/.config/git/private.inc` | Имя/email Git и личные настройки |
| `~/.pi/agent/` | Авторизация и история Pi; вход — `/login` |
| `~/.config/jevgrep/credentials.json` | Доступ Jevgrep; вход — `jg auth` |
| `~/.kube/`, `~/.ssh/`, `~/.config/xray-pi/` | Подключения, ключи и подписка прокси |

Файлы с секретами — 600, приватные каталоги — 700. Храните их вне Git,
восстанавливайте из защищённого хранилища и проверяйте пути на новом Mac.
OAuth-вход выполняйте заново. Удаление файла не очищает историю Git.

## Обслуживание

```sh
dots-tools setup cleanup           # только план удаления подтверждённых остатков
dots-tools setup cleanup --apply   # применить план
```

Уборка не удаляет действующие managed links, приватные настройки, бэкапы,
релизы и зависимости, не обходит чужие каталоги. `make test-go`,
`make test-node`, `make test-runner` запускают отдельные группы проверок:
Go-утилиты, браузерные группы задач и изолированные shell-сценарии соответственно.

Дополнительно: [VPN](vpn/README.md) и
[браузерные группы задач](tools/task-tab-groups/README.md).
Разовые отчёты храните в `$TMPDIR`; справочник параметров — в `--help`,
а не в копиях CLI-документации. Файлы skills/instructions — рабочие инструкции
агентов, не архив, и устанавливаются вместе с конфигами.
