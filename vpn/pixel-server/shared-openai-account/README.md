# Общий аккаунт OpenAI для сервисов

Отдельная интеграция: один владелец учётных данных публикует снимки доступа для потребителей.
Реальные аккаунты, адреса, токены и история развёртывания в репозитории не хранятся.

- `hermes_account.py` выбирает аккаунт, обновляет доступ под блокировкой и создаёт снимок.
- `shared_account_host.py` последовательно публикует атомарные файлы с проверкой владельца, прав и поколения.
- `staged/` содержит изменения для существующих приложений, не самостоятельные готовые сервисы.
- Потребители получают только access token, без секретов обновления; владелец авторизации остаётся единственным источником.

Метаданные `hermes_account` и идентичность JWT должны совпадать.
Поколение описывает выбранный аккаунт, не каждое обновление токена.
Гарантия — один снимок на запрос модели и последующая доставка выбранного аккаунта, а не мгновенная общая смена всех процессов.
Смена аккаунта не требует перезапуска потребителей; подтверждение доставки проверяется отдельно.
Источник политики должен быть недоступен потребителю для записи, без обходного изменяемого пути.

Перед применением проверьте версии целевых приложений, права файлов и резервные копии вне Git.
Старые маршруты `staged/crypto` требуют `DOTS_PROTON_ACCOUNT_ID` и `DOTS_PM_ACCOUNT_ID` в приватном окружении сервиса; `shared_account` работает без них.
Без нужного значения старый маршрут закрыт; действующие идентификаторы переносите через защищённое хранилище, не Git.
На новой машине выполняйте штатный вход заново; не собирайте общие архивы токенов.
