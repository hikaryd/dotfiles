# Pixel: инструкция для Hermes

> Переносимый runbook: адреса TEST-NET, имена и UID ниже — примеры,
> не описание вашей установки. Актуальные endpoints/ключи/результаты проверок
> храните в [приватном inventory](PRIVATE-CONFIG.md), не в Git.


## Браузер — доступ уже настроен

1. Для сайтов используй существующий `browser_exec`; Playwright MCP подключён
   к тому же настоящему Android Chrome. Не запускай вместо него новый headless.
2. CDP внутри `hermes-agent`: `http://127.0.0.1:19222`. Туннель создаёт сам
   Pixel → VPS; ноутбук и статический внешний домашний IP не нужны.
3. Для своей задачи открывай отдельную вкладку, запоминай её ID и закрывай её
   после завершения. Не закрывай чужие/активные вкладки для экономии памяти.
4. При недоступности CDP сделай ограниченный повтор. Owner-управление телефоном
   временно приостанавливает браузерный туннель; после stop/expiry он возвращается.
   При блокировке Android нужен ручной PIN владельца, обходить его нельзя.
5. Российские сервисы (включая Ozon/Avito и российские сервисы не на `.ru`)
   используют обычный Pixel flow **без дополнительных прокси даже при ошибке**.
   Существующие WG/маршруты не менять. Для явно нероссийских сервисов допустим
   только уже разрешённый proxy workflow по правилам SOUL.md; сообщать о смене
   runtime/fingerprint, не переносить cookies Pixel в него автоматически.

## Необязательная очередь браузера

После отдельной установки [concurrency/](concurrency/README.md) обычный
`browser_exec` работает через очередь без перезапуска gateway. Четыре фоновых
чтения могут идти параллельно; произвольный Python, клики и ввод — эксклюзивно.
Повторно используй worker-сессии `pixel_read_1`–`pixel_read_4`, а не создавай
бесконечное количество имён daemon. Каждый атомарный read-call получает новую
вкладку и закрывает её после чтения. Код вызова должен быть ровно:

```text
# pixel:read-v1
{"url":"https://example.org/","max_chars":20000}
```

Именованную интерактивную сессию завершай отдельным вызовом
`# pixel:finish-v1` с тем же `session`. Для новых задач используй
`pixel_ui_<task>`; сохранённые при миграции старые сессии могут вернуть
`preserved_unmanaged` — их вкладки автоматически не закрываются.
Не используй Playwright MCP или прямой
CDP одновременно с этим потоком: они обходят очередь. Cookies общие, это не
изолированные профили. VNC владельца по-прежнему прерывает туннель; при ошибке
не запускать другой Chrome и не обходить правило РФ без дополнительных прокси.
Переключение в owner-режим не мгновенное: мост замечает lease очередным опросом.
Не считать короткий переход атомарной блокировкой и не повторять прерванные
клики/отправку формы вслепую.
Установка VPN эту очередь не включает и не требует.

## SSH и управление — границы прав

- На телефоне есть owner SSH Termux: `192.0.2.116:8022`, user `u0_a123`.
  Адрес закреплён DHCP-резервацией на домашнем роутере.
- Владелец с настроенного Mac использует `ssh pixel` дома и `ssh pixel-remote`
  через VPS. Обратный owner SSH endpoint на **VPS host** — `127.0.0.1:19223`.
  Это не `localhost` контейнера Hermes и не его CDP-порт 19222.
- Эти команды используют **личный ключ владельца**, которого у Hermes нет.
  SSH-доступ владельца **не является выданным Hermes shell-доступом**.
  Не пробовать пароль панели/браузерный transport key, не запрашивать копию
  приватного owner/Termux/ADB ключа и не расширять forwarding ради доступа.
- Полный Termux shell способен читать ключи браузерного моста. Поэтому для
  будущих установок/домашних задач Hermes нужен отдельно согласованный
  ограниченный доступ; не утверждай, что уже можешь выполнять SSH-команды.
- Owner UI: `https://192.0.2.116:8443/`, только домашняя LAN и аутентификация
  владельца. Не предназначена для обхода разделения прав агента/владельца.

## Эксплуатация

Pixel используется для браузера, owner UI и Termux SSH. Установка гостевых
виртуальных машин и контейнерной платформы исключена из текущего плана.
Не возобновлять её без нового явного запроса владельца. Не включать root/reflash,
общие Android shares, открытый proxy или доступ ко всей LAN автоматически.

Вкладки автоматически закрываются по возрасту 12 часов, проверка каждые 5 минут;
возраст считается от первого наблюдения, не последнего действия. Не использовать
долгоживущую вкладку как единственное хранилище результатов. Reddit login сохранён;
Google-профиль Chrome вышел из аккаунта, Android-аккаунт владельца не удалён.
