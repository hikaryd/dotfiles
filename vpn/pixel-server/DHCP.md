# Постоянный LAN-адрес Pixel

Адрес и MAC берутся из приватного inventory, не из этого репозитория.
Ниже используются только TEST-NET примеры; они не являются адресами установки.
Перед применением идентичность сверяется через аутентифицированный ADB
и активную DHCP-аренду, затем проверяется сохранение резервации.

Это **внутренний**, а не внешний статический IP. Для исходящего обратного SSH-
туннеля Pixel → VPS постоянный внешний домашний IP не нужен.

## Проверить / восстановить

Из корня репозитория, пароль — только через окружение (не сохранять в Git):

```sh
read -s 'ROUTER_PASS?Пароль роутера: '; echo
export ROUTER_PASS
# Задать ROUTER_HOST, PIXEL_ADB_ENDPOINT и PIXEL_LAN_IP из приватного inventory.
export ROUTER_HOST
python3 vpn/pixel-server/reserve_dhcp.py \
  --adb-serial "$PIXEL_ADB_ENDPOINT" --expected-ip "$PIXEL_LAN_IP"
# Только при необходимости применить:
python3 vpn/pixel-server/reserve_dhcp.py \
  --adb-serial "$PIXEL_ADB_ENDPOINT" --expected-ip "$PIXEL_LAN_IP" --apply
unset ROUTER_PASS
```

Пример ввода пароля — для macOS/zsh. `ROUTER_HOST` обязателен; `ROUTER_USER` по умолчанию `admin`. Порт wireless ADB может измениться;
использовать актуальный аутентифицированный адрес из `adb devices`.
Не требуется постоянно подключать ноутбук: ADB здесь нужен лишь для
безопасной идентификации при установке/проверке резервации.

Скрипт по умолчанию ничего не меняет. Он отказывается действовать при
несовпадении адреса телефона и аренды роутера, конфликте IP/MAC или
неоднозначном DHCP-пуле. `--apply` добавляет только одну резервацию,
проверяет сохранность остальных резерваций/пулов и отправляет сохранение
конфигурации. VPN installer не вызывается; WG, маршруты, DNS и проброс
портов не изменяются. Уже существующая правильная резервация не заменяется.

**Не менять MAC/не забывать домашнюю Wi-Fi сеть без повторной проверки.**
Резервация привязана к текущему MAC сети, который может быть рандомизирован
Android. При его изменении скрипт не будет автоматически удалять или
переназначать старую резервацию. Новый роутер/сброс конфигурации также
потребует восстановления настройки. Обычная смена внешнего IP этому не мешает.

Команда соответствует официальному [Keenetic Command Reference,
`ip dhcp host`](https://storage.googleapis.com/docs.help.keenetic.com/cli/4.1/en/cli_manual_kn-2410.pdf)
(стр. 316–317). Используется существующий HTTP RCI helper из
`vpn/router-setup.py`, импортированный без запуска `main`/`install`.
