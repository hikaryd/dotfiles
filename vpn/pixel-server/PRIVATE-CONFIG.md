# Private installation inventory

VPN and Pixel are independent installations. Nothing in `../install.sh` reads
these files, contacts a phone or installs phone tooling. All IPs in examples
are documentation-only TEST-NET addresses; replace them with your own values.

Keep private inventory outside Git (for example `$HOME/.config/pixel-private/`)
or in ignored `vpn/private/`, directory mode 700, files mode 600. Include your
router host, reserved phone LAN IP/MAC, authenticated device serial/current ADB
endpoint, VPS SSH host and pinned host keys. Never publish rendered configs,
passwords, cookies, key fingerprints or installation diagnostic logs.

## Owner HTTPS / display helper

Create `$HOME/pixel-admin/control.json` on the phone from `control.example.json`:
use a fresh random control token, actual device serial and actual LAN IPv4.
`origin` must equal **exactly** `https://<lan_ip>:8443`; the helper refuses a
mismatch, missing identity, wildcard or non-private bind address. Serial checks
remain mandatory before display actions, including calls from the bridge.

Render `Caddyfile.template` with that same LAN IP and token plus private owner
credentials and Termux home. Retain exact Host/Origin and terminal deny rules.
Validate Caddy before activating it; do not copy an unrendered template live.
Use a certificate whose SAN matches the chosen IP, verified by trusted channel.

## Owner SSH

Copy `ssh-owner/inventory.example.json` to a private file and supply actual
`lan_ip` and `vps_host` (IPv4). Reserve the LAN address first. Installation inside
Termux is explicit:

```sh
python install.py --inventory "$HOME/pixel-private/ssh-inventory.json" \
  --owner-key "$HOME/pixel-private/owner.pub" \
  --vps-host-key "$HOME/pixel-private/vps-host.pub"
```

The installer stores mode-600 `~/pixel-owner/inventory.json`, renders the exact
LAN sshd bind and pins the supplied VPS host key. The supervisor reads this
inventory, never a built-in personal endpoint. Invalid/missing inventory is
fail-closed; SSH host key verification and loopback-only forwarding remain on.
Owner keys are not granted to Hermes. Private SSH client aliases are configured
separately on the owner's machine, not generated by VPN installation.

## Existing installations / migration boundary

This source cleanup does **not** alter any deployed config or service. Do not
replace the live helper or supervisor alone: first add `lan_ip` and `serial` to
the existing private `control.json`, preserving its token/origin, and create the
SSH inventory matching the existing rendered bind, destination and host keys.
Validate before any targeted service restart. The owner SSH installer intentionally
refuses reinstall over an existing owner directory; it is not a migration tool.
No router, phone, VPS or Hermes restart is part of this cleanup.

DHCP reservation now requires explicit `--expected-ip` and `ROUTER_HOST`;
VPN installer likewise prompts for or requires `--router-host`. Update private
automation inputs before its next run; existing deployed routing stays intact.
