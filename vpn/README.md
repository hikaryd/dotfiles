# AmneziaWG + sing-box split-VPN

Развёртывание домашнего VPN-шлюза «под ключ»:

```
Дом → Keenetic (AmneziaWG) → VPS → sing-box → подписка (VLESS/Reality) → интернет
        │                      │
        │                      └ geoip-ru → direct (выход с IP VPS)
        │                        остальное → подписка (заграничный выход)
        └ LAN-политика AWG_LAN разрешает только WG, без WAN-fallback
```

Возможности:
- **AmneziaWG** между роутером и VPS (обфускация WG против DPI).
- **sing-box** на VPS как прозрачный tproxy-шлюз: подписка `vless://…` → outbound'ы с авто-выбором быстрейшего узла.
- **Split-routing**: РФ (`geoip-ru`) идёт напрямую с IP VPS, всё остальное — через подписку.
- **Исключение**: `aquadx.hydev.org` принудительно идёт через подписку, до правил прямого выхода; его DNS — через `proxy-dns`, до adblock. Правило точное, без поддоменов.
- **Adblock** на уровне DNS (geosite ad-list) с whitelist для ложных срабатываний (TMDB/BunnyCDN).
- **Чистый DNS** через туннель — обход DNS-отравления РФ-провайдеров.
- **Панель** (zashboard / Clash API) — переключение узлов, пинги, трафик, логи.
- **LAN через HTTP RCI**: политика `AWG_LAN` разрешает только WG для сегмента `Home`; Entware и SSH к роутеру не требуются.
- **Failover самого роутера** на WAN через ping-check + самовосстановление (watchdog, авто-рестарт). Для LAN-политики WAN не разрешён.
- **Авто-обновление** подписки (systemd-таймер, 6 ч).

## Требования

- **VPS**: Debian/Ubuntu, root по SSH (по ключу), внешний UDP-порт доступен (1:1 NAT ок).
- **Роутер**: Keenetic/Netcraze, KeeneticOS **5.x** (нужна поддержка `wireguard asc`), доступ к веб-админке по HTTP. SSH, `sshpass`, `expect` и Entware на роутере не нужны.
- **Локально**: `bash`, `ssh`, `scp`, `python3`, `curl`. Запускать с устройства в сети роутера.

## Установка

```bash
./install.sh \
  --sub-url 'https://vpn.example/get_subscriptions/ТОКЕН' \
  --vps root@203.0.113.10 \
  --router-pass 'ПарольРоутера'
```

Без аргументов скрипт спросит обязательные параметры интерактивно. Все опции — `./install.sh --help`.
Запрос `SSH к VPS (root@IP)` остаётся: сервер устанавливается и регистрирует пиры через SSH.
Параметры `--router-ssh-port` и `--no-lan-hook` удалены.
HTTP-запросы к роутеру выполняются напрямую, без системного/локального прокси.
Приватный WG-ключ скрывается в сообщениях установщика. Повторное удаление уже
отсутствующих старых DNS не считается ошибкой; остальные ошибки RCI останавливают настройку.

Частые сценарии:

```bash
# только сервер (роутер настрою позже)
./install.sh --sub-url URL --vps root@IP --skip-router

# только роутер (сервер уже развёрнут — пир зарегистрируется на VPS)
./install.sh --vps root@IP --router-pass PASS --skip-vps

# свой порт/подсеть/без adblock
./install.sh --sub-url URL --vps root@IP --router-pass PASS \
  --awg-port 51820 --tunnel-net 10.8.2.0/24 --no-adblock

# LAN-сегмент с нестандартным именем (имя интерфейса Keenetic, не SSID)
./install.sh --vps root@IP --router-pass PASS --skip-vps \
  --router-lan-interface Bridge1
```

### LAN-политика без SSH к роутеру

Через HTTP RCI установщик создаёт/обновляет собственную политику `AWG_LAN`:
`no permit auto`, `permit global Wireguard0`, затем явно запрещает остальные
глобальные интерфейсы через `no permit global <ID>` и назначает её
командой `ip hotspot policy Home AWG_LAN` и сохраняет конфигурацию. Имя
LAN-интерфейса проверяется до изменений роутера; другой сегмент задаётся
через `--router-lan-interface`. Список глобальных интерфейсов читается через HTTP до изменений. Команда
`no permit` без имени интерфейса не используется: KeeneticOS может её отклонять.
Пользовательский `Policy0` не меняется.
Назначение выбранного сегмента заменяется; имя `AWG_LAN` зарезервировано установщиком.
Синтаксис политик описан в [официальном справочнике Keenetic, разделы 3.44.8 и 3.67](https://storage.googleapis.com/docs.help.keenetic.com/cli/4.1/en/cli_manual_kn-2410.pdf).
Интерфейсы читаются через `POST /rci/show` с `[{"interface":{"name":"Home"}}]`:
`Home` — алиас, а системный ID может быть `Bridge0`. Подстановка алиаса в URL
`/rci/show/interface/Home` может вернуть 404; формат запроса приведён в
[справочнике RCI, приложение B](https://storage.googleapis.com/docs.help.keenetic.com/cli/3.1/en/cli_manual_kn-2210.pdf).

Если предыдущий запуск остановился на настройке роутера после успешной установки VPS,
повторный запуск `./install.sh --vps root@IP --skip-vps` пропустит установку сервера
и переиспользует запись пира. Пароль роутера будет запрошен интерактивно.

Если SSH к VPS проходит через настраиваемый VPN, перезапуск туннеля или sing-box
может оборвать установочное соединение. Установщик запускает серверный скрипт с
`nohup`; тот сохраняет результат текущего запуска с правами `0600` **до** вывода
в SSH. При коде SSH `255` установщик переподключается до шести раз и продолжает
только при наличии полного результата именно этого запуска и активности каждой
из служб `awg-quick@awg0`, `awg-gateway`, `sing-box`. Сам факт доступности SSH не
считается успешной установкой; повторный запуск установки автоматически не выполняется.
После чтения временный результат удаляется. Ввод пароля роутера не отображается.

Ограничения:
- Индивидуальные политики/access-правила клиентов имеют приоритет над политикой сегмента; установщик их не перезаписывает.
- Другие LAN/гостевые сегменты не переназначаются.
- Ранее установленный `/opt/etc/ndm/netfilter.d/50-lan-via-wg` через HTTP не удаляется и может продолжать влиять на маршруты. Автоматической миграции старого Entware-хука нет.
- Это не проверенная гарантия отсутствия утечек: поведение IPv6, индивидуальных правил и отключения туннеля нужно проверять на целевом роутере.

## Несколько роутеров на один сервер

Каждый роутер получает **свой ключ и свой IP** в туннельной подсети — реестр
пиров живёт на VPS в `/root/awgvpn/peers/<имя>/`. Имя берётся из hostname
роутера автоматически (или задаётся `--router-name`).

```bash
# роутер №1 (полная установка, из его сети)
./install.sh --sub-url URL --vps root@IP --router-pass PASS1

# роутер №2 (из его сети; сервер не трогаем, пир добавляется на лету)
./install.sh --vps root@IP --router-pass PASS2 --skip-vps
```

Повторный запуск для того же роутера переиспользует его запись (идемпотентно):
роутер опознаётся по hostname и по текущему WG-ключу, так что сервер,
развёрнутый старой версией скрипта, мигрирует без разрыва. Добавление пира
применяется через `awg syncconf` — сессии остальных роутеров не рвутся.

Управление реестром (на VPS):

```bash
bash /root/awgvpn/peer-register.sh list           # список пиров
bash /root/awgvpn/peer-register.sh remove ИМЯ     # отцепить роутер
```

## Файлы

| Файл | Назначение |
|------|-----------|
| `install.sh` | Оркестратор: аргументы, preflight, запуск частей, проверка, итог |
| `vps-setup.sh` | Серверная часть (выполняется на VPS): AWG + sing-box + nftables + службы |
| `peer-register.sh` | Реестр пиров на VPS: свой ключ/IP каждому роутеру, живое добавление/удаление |
| `generate.py` | Генератор `config.json` sing-box из подписки (читает `/etc/sing-box/vpn.env`) |
| `router-setup.py` | Настройка Keenetic только через HTTP RCI (AWG-клиент, LAN-политика, ip global, ping-check, DNS); режим `identify` |

## После установки

- Панель: `http://<VPS_IP>:9090/ui/`, пароль печатается в конце установки (и лежит в `/etc/sing-box/secret.txt` на VPS). Открывать по **http** (не https).
- На устройствах обнови аренду DHCP (переподключи Wi-Fi), чтобы получить роутер как DNS — иначе кэш старого DNS может мешать.

### Управление (на VPS)

```bash
# сменить подписку / вкл-выкл adblock
nano /etc/sing-box/vpn.env        # SUB_URL=… , ADBLOCK=1|0
python3 /etc/sing-box/generate.py && systemctl restart sing-box

# статус
systemctl status sing-box awg-quick@awg0 awg-gateway
awg show awg0
```

### Whitelist adblock

Если adblock ложно блокирует домен (картинки/CDN не грузятся) — добавь его в
`ADBLOCK_WHITELIST` в `/etc/sing-box/vpn.env` (через запятую) и перегенерируй конфиг.

## Заметки

- При падении туннеля сам роутер может перейти на WAN; политика `AWG_LAN` не разрешает прямой WAN-выход для назначенных ей клиентов.
- РФ-сайты на зарубежных CDN (Cloudflare и т.п.) пойдут через VPN — ограничение geoip.
- `xhttp`-узлы из подписки пропускаются (sing-box их не поддерживает).
