# VPN-шлюз

Скрипты настраивают AmneziaWG между роутером и VPS и sing-box для разделения маршрутов.
Нужны Debian/Ubuntu на VPS, SSH по ключу, совместимый роутер Keenetic/Netcraze с HTTP RCI.
На машине запуска: Bash, SSH/SCP, Python 3 и curl; она должна видеть роутер напрямую.

```sh
cd vpn
./install.sh --help
./install.sh
```

Без аргументов установщик запрашивает параметры. Пароли и ссылку подписки не помещайте в историю команд.
Настройка меняет VPS и/или роутер: заранее проверьте выбранные адреса и сохраните резервные копии.
`--skip-router` пропускает роутер; `--skip-vps` использует уже установленный сервер.
Адрес роутера задаётся явно; реальные параметры храните вне Git, например в `vpn/private/` (каталог `700`, файлы `600`).

## Ограничения

- Политика `AWG_LAN` разрешает выбранному LAN-сегменту только туннель, но сам роутер может переключаться на WAN.
- Назначение выбранного сегмента заменяется; другие сегменты и индивидуальные политики не перезаписываются.
- Индивидуальные правила имеют приоритет. IPv6 и отсутствие утечек нужно проверять на конкретном роутере.
- Старые сторонние сетевые хуки автоматически не удаляются; geoip не определяет страну владельца сайта.
- Для повторной настройки только роутера используйте `--skip-vps`; не повторяйте полную установку вслепую после обрыва SSH.
- Генератор разбирает `vless://`, `hysteria2://` и `hy2://`. Hysteria2 использует
  адрес, пароль, SNI/TLS, порты и obfs из URI без привязки к провайдеру или стране.
  XHTTP не поддерживается sing-box в этой реализации: такие строки получают явный
  `skip line N: xhttp transport is not supported by sing-box`. Другие неподдерживаемые
  протоколы и некорректные параметры тоже отмечаются; пропуск не доказывает отказ узла.

На VPS: конфигурация `/etc/sing-box/vpn.env`, секрет панели `/etc/sing-box/secret.txt`, реестр пиров `/root/awgvpn/peers/`.
Проверка служб: `systemctl status sing-box awg-quick@awg0 awg-gateway`.
Панель слушает HTTP на порту `9090`; не открывайте её в недоверенную сеть без защищённого доступа.

Браузерный телефон для агентов настраивается отдельно в `~/Documents/dev/agent-phone/`;
установщик VPN его не меняет.
[Хранение и перенос секретов](../docs/PRIVATE.md).

## Оптимизация и наблюдение

- Автопул: до **8** уникальных конфигураций в порядке подписки, без LTE/3G/4G
  и «Обход БС». Это ограничение числа проверок, не обещание максимальной скорости.
  Все разобранные узлы и их имена остаются в ручном selector, включая исключённые из auto.
- В `/etc/sing-box/vpn.env` можно задать `AUTO_INCLUDE` и `AUTO_EXCLUDE`
  (регулярные выражения без учёта регистра), `AUTO_MAX` (положительное число).
  Пустой `AUTO_EXCLUDE=` отключает фильтр. Если кандидатов нет или конфиг невалиден,
  генератор не заменяет рабочий `config.json`. Эти параметры сохраняются при повторной
  полной установке; `--skip-vps` вообще не меняет настройки сервера.
- `AUTO_PREFER` — regex по имени узла без учёта регистра: после include/exclude
  совпавшие узлы идут первыми перед дедупликацией и `AUTO_MAX`, с сохранением порядка
  внутри групп. По умолчанию пуст; ручной selector не меняет.
- Панель доступна через туннель: `http://10.8.2.1:9090/ui/` для стандартной подсети.
  Firewall разрешает порт панели только с `awg0` и loopback. Вне VPN:
  `ssh -N -L 9090:127.0.0.1:9090 root@VPS`, затем `http://127.0.0.1:9090/ui/`.
  Пароль по-прежнему обязателен. Не открывайте порт на внешнем интерфейсе.
- `vpn-health.timer` раз в 2 минуты проверяет HTTPS через локальный SOCKS-вход
  sing-box и выбранный прокси. Два независимых адреса, нужен HTTP 204 хотя бы от одного.
  Проверка не использует прямой fallback и ничего не перезапускает.
  `systemctl status vpn-health.service` и `journalctl -u vpn-health.service`
  показывают результат и переходы failed/healthy. Это не внешняя система оповещений.
- Диагностический порт `HEALTH_PORT=7896` слушает только `127.0.0.1` и дополнительно
  закрыт firewall для остальных интерфейсов. Его значение сохраняется при переустановке.
  Проверка доказывает работу прокси HTTPS с доменным именем, но не отдельного
  `proxy-dns`, Wi-Fi, роутера или всей цепочки LAN→AWG. Их проверяют отдельно.
- MTU остаётся **1280**. Поднимать его и менять буферы следует только по измерениям.

Для второго дома на том же VPS запускайте `./install.sh --skip-vps`: существующие
пиры сохраняются, новый роутер получает отдельный адрес/ключ. Адрес роутера и пароль
можно ввести интерактивно. Реальное подключение второго дома проверяется из его LAN.

BBR для TCP, отправляемого VPS конкретному дому, включается отдельно после замера:
на VPS выполните `python3 tcp-tuning.py install --peer 10.8.2.2/32`. Адрес должен
совпадать с реальным AllowedIP пира `awg0`; несколько `--peer` задают полный список.
Без `--peer` установка сохраняет `/etc/awg-tcp-tuning.json` (0600); на новом VPS
список пуст. Служба `awg-tcp-tuning.service` восстанавливает настройку после перезапуска
AWG, а установка самой службы не перезапускает AWG. Глобальные Cubic/qdisc и остальные
пиры не меняются. Откат: `python3 /usr/local/libexec/awg-tcp-tuning.py disable`.
Он удаляет только маршруты этой службы и сбрасывает список выбранных пиров.
Изменение действует для новых TCP-соединений. BBR может повысить скорость ценой
повторных передач; он не устраняет слабый Wi-Fi и предел CPU роутера и не гарантирует
400 Мбит/с. Пересылка TCP через VPS и UDP-туннель сами по себе не получают новый CC.

Локальные проверки: `python3 -m unittest discover -s vpn/tests -v`,
`ruff check vpn/generate.py vpn/benchmark.py vpn/tcp-tuning.py vpn/tests`, `shellcheck -e SC2029 vpn/*.sh`.

Справка sing-box: [URLTest](https://sing-box.sagernet.org/configuration/outbound/urltest/),
[Clash API](https://sing-box.sagernet.org/configuration/experimental/clash-api/),
[Mixed inbound](https://sing-box.sagernet.org/configuration/inbound/mixed/).

### Измерение скорости перед выбором автопула

`benchmark.py` запускает отдельный sing-box с авторизованным localhost-входом:
рабочий selector, firewall и службы не меняет. Секреты остаются на VPS, временный
конфиг удаляется. Требуются уже установленные sing-box, curl и Python.

Сначала скачайте **свежую сырую подписку** и разберите все её строки актуальным
генератором. Следующий пример выполняется на VPS из каталога с актуальными
`generate.py` и `benchmark.py`; URL берётся из защищённого `/etc/sing-box/vpn.env`.
Импорт не вызывает `main`: используются `fetch`/`parse_subscription`, рабочий конфиг не заменяется:

```sh
umask 077
export VPN_BENCH_CONFIG="$(mktemp)"
python3 - <<'PY'
import json, os, runpy
from pathlib import Path
g = runpy.run_path("generate.py")
try:
    raw = g["fetch"](g["SUB_URL"])
except Exception:
    raise SystemExit("Не удалось скачать подписку; конфиг не создан.") from None
nodes = g["parse_subscription"](raw)
if not nodes:
    raise SystemExit("Нет поддерживаемых узлов; проверьте сообщения skip line.")
count = sum(bool(line.strip()) for line in raw.splitlines())
Path(os.environ["VPN_BENCH_CONFIG"]).write_text(
    json.dumps({"outbounds": nodes}, ensure_ascii=False), encoding="utf-8")
print(f"Строк: {count}; разобрано: {len(nodes)}; пропущено: {count - len(nodes)}")
PY
python3 benchmark.py --config "$VPN_BENCH_CONFIG" --all
```

`--all` проверяет все proxy outbounds **переданного конфига**, включая Hysteria2,
а не только прежний auto; сам подписку не скачивает. Selector/urltest/direct/block/dns
не считаются узлами, прямой выход VPS добавляется отдельно. Сопоставьте количество
разобранных строк и причины пропусков: XHTTP и другие неподдерживаемые записи
не входят в измеренное покрытие.

Для `--all` defaults: **1 проба × 1 MB, timeout 10 s** — первичный screening.
Без `--all`: текущий автопул + прямой выход, 2 пробы × 10 MB, timeout 20 s.
`--only 'точное имя узла'` повторяется для финалистов любого поддерживаемого
proxy-протокола; `--extra` добавляет ручной узел к auto. Например, сравнение
финалиста по двум источникам (файл OVH имеет ровно **10485760 байт**):

```sh
python3 benchmark.py --config "$VPN_BENCH_CONFIG" --only 'точное имя узла' \
  --samples 3 --bytes 10485760 --timeout 20 \
  --url 'https://speed.cloudflare.com/__down?bytes={bytes}' \
  --url 'https://proof.ovh.net/files/10Mb.dat'
```

После сравнений удалите временный конфиг: `rm -f "$VPN_BENCH_CONFIG"`.

`--url` повторяется до 4 раз и заменяет Cloudflare по умолчанию; `{bytes}`
подставляет размер пробы. Нужны HTTP 200 и **точное** совпадение размера, поэтому
статический файл другого размера считается ошибкой. Секреты в URL не используйте.
Оценка трафика: `(число узлов + 1) × samples × bytes × число уникальных URL`.
Границы: samples 1–5, bytes 1–50000000, timeout 1–30 s; до 16 узлов без `--all`.
`--max-duration` задаёт общий бюджет до 86400 s; по умолчанию он вычисляется из
числа проб и таймаутов, с тем же пределом. Исчерпание отмечается как skipped;
очистка процесса может занять ещё до 10 s.

Узлы и источники чередуются. JSON показывает protocol, progress, время, failures/skipped
и отдельные медианы успешных проб по узлу/источнику. Exit 1 означает хотя бы одну
пару без успешных проб или неполный прогон из-за skipped. Это тест **VPS→узел→источник**;
после него отдельно нужны чередующиеся LAN-пробы финалистов. По результатам настройте
`AUTO_INCLUDE`/`AUTO_MAX` в `vpn.env`; универсальный набор стран для всех VPS не существует.
Не подбирайте маршрутизацию специально под speedtest и не объявляйте один удачный
пик общим ускорением.

### Отдельная проверка XHTTP через Xray

XHTTP-строки сырой подписки учитываются как неподдерживаемые sing-box и проверяются
отдельно через `xhttp-benchmark.py`. Скрипт сохраняет XHTTP из URI, не заменяет его
на TCP и не добавляет узел в рабочий auto. Повторите проверку для каждой такой строки.

На Linux x86_64 VPS из каталога скрипта задайте `XHTTP_INDEX` номером нужной строки
**с нуля**, включая пустые строки (он соответствует `N` в `skip line N`). Скрипт
сам скачивает свежую подписку по `SUB_URL` из `/etc/sing-box/vpn.env`; после изменения
порядка строк индекс нужно проверить заново. `--check-only` проверяет конфиг Xray,
соединение с узлом при этом не проверяется:

```sh
python3 xhttp-benchmark.py --source-index "$XHTTP_INDEX" --check-only
python3 xhttp-benchmark.py --source-index "$XHTTP_INDEX" \
  --samples 3 --bytes 10485760 --timeout 20 --max-duration 240 \
  --url 'https://speed.cloudflare.com/__down?bytes={bytes}' \
  --url 'https://proof.ovh.net/files/10Mb.dat'
```

Первый запуск загружает закреплённый Xray **26.3.27** в `tools/xray-26.3.27/`
рядом со скриптом и проверяет SHA256 архива. `--install-only` выполняет только эту
подготовку. Тест использует отдельный процесс и авторизованный SOCKS на localhost;
временные конфиги/логи удаляются, рабочие службы и маршруты не меняются.

Defaults: 3 пробы × 10 MB, timeout 20 s, общий бюджет 240 s. Допустимы samples 1–5,
bytes 1–50000000, timeout до 30 s, бюджет до 86400 s; до 4 HTTPS-источников через
повторяемый `--url`/`--url-template`, с `{bytes}` и точной проверкой HTTP 200/объёма.
JSON содержит trial, общий summary и source_summary; ошибки имеют безопасные коды.
Любая неуспешная или пропущенная проба даёт exit 1. Это измерение выхода VPS через
XHTTP; скорость Wi-Fi, AWG и всей цепочки LAN проверяется отдельно.
