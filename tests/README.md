# Проверки рабочего окружения

Из корня репозитория:

```sh
make test          # все собственные наборы
make test-go       # все Go-модули: race + vet
make test-python   # установщики, Herdr task titles, VPN
make test-node     # quota/throughput status bar
make test-runner   # контракт запуска тестов, с подставными runtimes
make test-list     # состав наборов, без запуска
```

Эквивалент без Make: `./scripts/test.sh [all|go|python|node|runner|--list]`.
Можно вызвать скрипт из другого каталога; он сам переходит в корень репозитория.
Нужны Bash, Go с поддержкой `-race`, Python 3 и Node.js с `node:test`.
`PYTHON_BIN`, `GO_BIN`, `NODE_BIN` позволяют явно выбрать установленные runtimes.

## Организация

Тесты остаются рядом со своим кодом и используют стандартный runner языка:

| Код | Тесты | Framework |
|---|---|---|
| Установщики и read-only inventory uninstall | `scripts/tests/test_*.py` | `unittest` |
| Herdr task titles | `config/herdr/plugins/task-titles/test_*.py` | `unittest` |
| VPN protocol/config/benchmark/tuning | `vpn/tests/test_*.py` | `unittest` |
| Herdr last workspace | `tools/herdr-last-workspace/*_test.go` | `go test -race` |
| Все Go-модули утилит | `tools/*/go.mod` | `go test`, `go vet` |
| Status bar calculations | `config/pi/tests/*.test.mjs` | `node:test` |
| Test runner | `tests/test-runner.sh` | Bash, fake runtimes |

Не добавляем pytest, сторонний assert-framework или второй runner поверх
стандартного. Новый Python-тест с именем `test_*.py` попадает в свой набор
автоматически; новый Go-модуль под `tools/` также включается автоматически.
Новая Python-директория или Node-набор требуют явного добавления в `scripts/test.sh`.

**`python3 -m unittest discover` из корня не является проверкой репозитория:**
он может найти ноль тестов. Общая команда задаёт каталоги явно и отклоняет
пустой Python/Node-набор, даже если native runner вернул exit 0.
Сбой или отсутствующий runtime не скрывается. Остальные независимые наборы
продолжают выполняться, затем общий runner печатает итог и возвращает exit 1.
Результаты Go-тестов не берутся из cache (`-count=1`); toolchain не скачивается
автоматически (`GOTOOLCHAIN=local`). Строка `[no test files]` остаётся видимой:
прохождение компиляции/вета не означает наличие regression-покрытия.

## Безопасность

- Существующие тесты используют временные каталоги, fixtures и подставные
  команды. Production install/uninstall, VPN-настройка, реальные Herdr-сессии
  и загрузка подписок не запускаются.
- OS-проверки используют собственный Unix-сокет или localhost listener и
  созданные тестом дочерние процессы. Их не следует заменять mock всех вызовов:
  иначе потеряется проверка блокировки и реальной очистки процессов.
- Python-наборы получают временные `HOME`/XDG-каталоги и `VPN_ENV=/dev/null`:
  импорт VPN-генератора не должен читать настоящую конфигурацию VPS.
- Это ограничения тестового harness, **не OS sandbox**. Новые тесты необходимо
  проверить на побочные эффекты до добавления в общую команду.
- Собственный runner не рекурсирует в сторонний Dotbot, виртуальные окружения,
  архивы и приватные конфиги. Временные логи удаляются после запуска.

## Какие тесты оставлять

Проверять поведение через используемый вызывающим кодом interface: сохранение
настроек и auth, ошибки без секретов, владение ресурсами, переключение workspace,
таймауты, rollback и cleanup. Табличные варианты одного правила допустимы;
разные протоколы и разные области владения не считаются дубликатами только из-за
похожих assert.

Удалять тест вместе с удалённой возможностью либо когда другой тест действительно
покрывает то же поведение через тот же interface. Не удалять regression-тест
ради уменьшения числа файлов или общего количества assert. При переносе на Go
сначала перенести проверяемое поведение, проверить native replacement и его
вызывающий код, затем убрать прежнюю реализацию и её набор.

Текущий пробел: у Kubernetes Go watchers нет `*_test.go`, у `codex_config.py`
и большей части `dots-*` тоже нет characterization-наборов. Перед их
переписыванием нужны fixtures для парсинга, сохранения пользовательских данных
и failure paths; текущий зелёный прогон этого не доказывает.
