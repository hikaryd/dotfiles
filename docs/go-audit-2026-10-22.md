Историческая выдержка: после отделения самостоятельного инструмента оставлены результаты только для компонентов dots. Инвентари исходного аудита не описывают текущий состав репозитория; полный первоначальный отчёт сохранён вне публичных дотов.

После изменений: 128 production-файлов и 104 тестовых файла (232 Go-файла). Исходники тестов изучались с разной глубиной; полного аудита каждой тестовой проверки не заявляем.
- В оставшейся части отчёта **20 находок: 15 P1 и 5 P2**. Исправлены 19; одна P2 о точности истории Herdr остаётся ограничением внешнего контракта. Это число записей ревью, не число независимых уязвимостей: некоторые симптомы имели общий корень.
- Повторные проверки конфигов/desktop и proxy/protocol выявили и закрыли ранний сбой metadata при импорте workspace и слабую проверку лимита tool arguments.
- Последний полный `./scripts/test.sh` прошёл. Однако предыдущий полный запуск имел три неповторившихся пятисекундных таймаута; это ограничение уверенности, а не доказанный исправленный дефект. Подробности ниже.
- Сохранены исходные пользовательские изменения в `tools/dots/internal/proxy/proxy.go`, исходные untracked OpenCode-файлы и `tools/dots/internal/proxy/opencode_test.go`. Их корректировки не заменялись версией из HEAD.
- На момент завершения аудита изменения оставались незакоммиченными; затем пользователь запросил общий commit исходников, тестов и документов. Перед commit повторный полный `./scripts/test.sh` прошёл без ошибок. Push и установка не выполнялись. Реальные кластеры, launchd jobs, VPN, router и desktop workspaces не изменялись.

## Сквозные изменения и границы ответственности

1. **Terminal trust boundary:** `tools/dots/internal/tui/escape.go` различает plain untrusted text и application-owned styling. Selector сохраняет исходное значение отдельно; display sanitization не переписывает аргументы выбранной команды.
2. **Process/service ownership:** `tools/dots/internal/launchd/job.go` проверяет фактический loaded job, а не только label или disk file. Pi cancellation относится к direct child, а не к независимо управляемому proxy service.
3. **Fail-closed desktop reuse:** partial workspace не признаётся completed по совпадению name/path. Автоматическая достройка/удаление частичного workspace не выполняется; доступ по явному Herdr ID остаётся для ручного восстановления.

## Проверки и доказательства

### Выполнено родителем

```sh
./scripts/test.sh
# Последний запуск: Failed suites: 0
# Обе Go modules: go test -race -count=1 ./... и go vet ./...
# 5 shell-contract suites; 129 Node tests, 129 pass, 0 fail

GOOS=linux GOARCH=amd64 CGO_ENABLED=0 GOTOOLCHAIN=local \
  go -C tools/dots test -exec /usr/bin/true ./...
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 GOTOOLCHAIN=local \
  go -C tools/herdr-last-workspace test -exec /usr/bin/true ./...
# Обе команды успешны: compile-only, не Linux runtime verification.

git diff --check
```

Среда исполнения: Go `go1.27.3 darwin/arm64`. Помимо финального прогона выполнялись focused RED→GREEN проверки по областям. После замечания proxy reviewer `TestToolStreamAggregateBound` усилен валидным fragmented JSON и проверками по обе стороны лимита; временное отключение aggregate guard заставило oversized case упасть, после восстановления guard тест прошёл.

**Нестабильность исторического прогона:** один запуск завершился с тремя пятисекундными таймаутами в позднее отделённом инструменте. На том же коде focused `-race -count=5` и повторный полный suite прошли. Причина **не доказана**; тесты не отключались и таймауты не увеличивались. Эти наблюдения не заменяют проверку актуального дерева.

### Диагностика и ограничения reviewers

- Active LSP probe: 71 изменённый Go-файл, 35 clean, 28 с findings, 8 inconclusive; unsupported/unavailable/failed — 0. При threshold warning получены 159 warnings: 16 primary (WriteString/fmt allocation suggestions) и 143 auxiliary pattern warnings. Ошибок probe не сообщил, но результат **не lint-clean** и 8 файлов не подтверждены сервером. Среди auxiliary есть нерелевантные CLI-print/WaitGroup/map heuristics; они не автоматически считаются дефектами и не были механически «исправлены».
- Reviewers имели read-only source access без execution tools. Их source verdicts не выдаются за независимый запуск тестов. Runtime regressions запускал родитель.
- Начальные scoped `jg`-поиски родителя не дали результата за 180 секунд; discovery продолжен локально по инвентарям и исходникам. Пустой search output не использован как доказательство отсутствия кода.
- Go regression fixtures проверяют block lifecycle и reconstruction; реальный внешний Anthropic SDK end-to-end в этой работе не запускался.
- Реальные router firmware, sing-box/Xray handshakes, launchd output на разных macOS, browser preferences и Herdr event ordering динамически не проверены. Linux проверен только компиляцией. Windows не заявлен поддерживаемой/проверенной целью.

## Нерешённое ограничение Herdr (V4)

Сейчас корректная формулировка поведения — «предыдущий **наблюдённый** workspace», не гарантированно предыдущий фактически сфокусированный. При быстрых переходах stale-hook guard правильно предотвращает out-of-order overwrite, но может отбросить промежуточный focus. Простое удаление guard заменило бы один дефект другим.

Для полноценного решения нужен контракт Herdr с ordered sequence/previous-workspace identity либо авторитетной историей focus events. Такой контракт в доступном источнике не установлен. Go-код Herdr не менялся; ограничение явно остаётся открытым, а не объявлено исправленным.
