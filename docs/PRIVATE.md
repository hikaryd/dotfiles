# Приватные настройки и перенос

Репозиторий содержит только шаблоны. Личные адреса, ключи и рабочие проекты — вне Git.

```sh
dots private init    # создать только отсутствующие шаблоны с правами 600
dots private check   # проверить права и незаполненные поля без вывода значений
```

Без аргумента `dots private` выполняет проверку. Существующие файлы не перезаписываются.
Проверка эвристическая: права, пустота и известные шаблоны, не полнота каждой переменной и не работоспособность ключей.
`init` готовит четыре файла: настройки оболочки, Git и секреты MCP для Claude/Codex.
Заполняйте их редактором, а не командами с паролями в истории терминала.

## Что где хранить

| Файл или каталог | Содержимое |
| --- | --- |
| `~/.config/dots/private.zsh` | Личные алиасы, адреса API, пути и контексты Kubernetes; шаблон `config/zsh/private.example.zsh` |
| `~/.config/dots/account-routes.env` | Необязательные `DOTS_PROTON_ACCOUNT_ID` / `DOTS_PM_ACCOUNT_ID` для старых маршрутов staged-сервисов; подключать только в окружение нужного сервиса, не глобально |
| `~/.config/git/private.inc` | Имя/email Git и личные `maintenance.repo`; подключён общим конфигом Git |
| `~/.claude/.mcp-secrets` | `Z_AI_API_KEY`, `MAGIC_API_KEY`, `KUBECONFIG_PATH`, необязательный `ANTHROPIC_BASE_URL` |
| `~/.codex/.mcp-secrets` | `Z_AI_API_KEY`, необязательный `CF_OPENAI_BASE_URL` |
| `~/.kube/` | Выданные kubeconfig; пути к ним задаются в `private.zsh` |
| `~/.ssh/` | Клиентские настройки и проверенные `known_hosts`; ключи предпочтительно через менеджер паролей/SSH-агент |
| `~/.config/xray-codex/` | Приватная подписка и конфигурация прокси, если он используется |
| `~/.config/agent-phone/` | Адреса, инвентарь и публичные ключи телефона; шаблоны в `~/Documents/dev/agent-phone/` |

Пути учитывают `DOTS_PRIVATE_ZSH`/`XDG_CONFIG_HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_CONFIG_DIR`/`CODEX_HOME`; Git include фиксирован: `~/.config/git/private.inc`.

Для файлов с секретами нужны права `600`, для приватных каталогов — `700`.
Необязательные интеграции можно не заполнять; предупреждение о шаблоне не означает, что нужен новый аккаунт.
Не копируйте примеры адресов/контекстов в рабочую настройку без проверки.

## Новый компьютер

1. Сохраните перечисленные нужные файлы в защищённом хранилище менеджера паролей. Не собирайте открытый архив с секретами.
2. Установите репозиторий и выполните `dots private init`.
3. Восстановите выбранные файлы из хранилища либо передайте их через SSH с проверкой ключа получателя. Не переносите весь домашний каталог.
4. Исправьте пути в `private.zsh`, Git и kubeconfig; восстановите доступ SSH через менеджер ключей. Закрытые ключи телефона не переносите.
5. Выполните `dots private check`, затем откройте новую оболочку. Команда проверяет четыре подготовленных файла, не все внешние хранилища и не доступность сервисов.
6. После заполнения MCP примените нужную интеграцию: `bash scripts/claude-apply.sh` и/или `bash scripts/codex-apply.sh`. Они обновляют соответствующие конфиги с резервными копиями.
7. В CLI с OAuth выполните вход заново штатной командой. Не копируйте автоматически токены, cookies и активные сессии.
8. Выполните `dots projects refresh`: список проектов и абсолютные пути формируются заново.

Рабочие файлы и резервные копии секретов не добавляйте в Git. Очистка текущих исходников не удаляет прежние значения из истории Git.
