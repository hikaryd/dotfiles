# kubedesk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выделить существующий Kubernetes/metrics TUI в публичный `hikaryd/kubedesk`, выпустить `v0.1.0` для macOS/Linux и перевести dots на этот релиз без потери настроек и привычных команд.

**Architecture:** Скопировать разрешённый snapshot Go-пакетов в независимый module, сохранив поведение и тесты. Новый продукт самостоятельно выбирает конфиги, устанавливает алиасы и запускает watchers. После проверки опубликованных assets dots получает только закреплённый release installer и тонкий Unix exec-forwarder; второй копии Kubernetes/metrics кода не остаётся.

**Tech Stack:** Go `1.26.0`, текущие версии Go-зависимостей, Bash для сборки архивов, GitHub Actions/Releases, macOS/Linux, fake kubectl/HTTP и PTY-тесты.

**Spec:** `docs/superpowers/specs/2026-10-20-kubedesk-design.md` в dots; перед выполнением читать целиком. Дизайн одобрен пользователем 2026-10-20.

## Global Constraints

- Go module: `github.com/hikaryd/kubedesk`; toolchain `go 1.26.0`. Не совмещать перенос с обновлением зависимостей. Ни `go.work`, ни локального `replace`, ни runtime/build-зависимости на dots.
- Имя продукта и бинарника `kubedesk`; публичный репозиторий `github.com/hikaryd/kubedesk`; первый релиз `v0.1.0`.
- Только `dev/stage/preprod/prod`; сохранить текущие CLI, клавиши, preview, алиасы, `KUBE_*`, `KPROD_CONFIRMED`, `NO_COLOR`, `KUBECONFIG` и поддерживаемые XDG-переменные.
- Не переименовывать contexts `dots-dev/stage/preprod/prod`, generic пути `kube-tools` и `~/Documents/kube-logs`. Не копировать и не удалять автоматически приватные конфиги.
- Новые конфиги: `${XDG_CONFIG_HOME:-~/.config}/kubedesk/sources.yaml`, соседний `contexts/`, `kubedesk/metrics.json`; приватный metrics inventory при config-каталоге в Git — `${XDG_DATA_HOME:-~/.local/share}/kubedesk/metrics.json`.
- Legacy: `dots-kube/sources.yaml`, `dots-kube/metrics.json`, `dots-private/metrics.json`. Новый существующий файл приоритетен, даже если ошибочен; без слияния полей/скрытого fallback. Metrics `--config` выше defaults; `init` не перезаписывает файлы.
- Metrics inventory/bearer: regular files `0600`/`0400`, вне Git, без symlink-файлов; сохраняются lexical/resolved проверки родителей. HTTPS для удалённых URL, HTTP только loopback; никаких TLS bypass, shell HTTP proxy и секретов в диагностике.
- Pinning kubeconfig/context/namespace и prod guard сохраняются. Обычный setup не меняет исходный kubeconfig или глобальный current-context. Прямой metrics URL не требует kubectl; port-forward требует.
- Сборки `CGO_ENABLED=0`, `-trimpath`; четыре платформы `darwin/arm64`, `darwin/amd64`, `linux/arm64`, `linux/amd64`. CI с тестами на macOS и Linux. Cross-build не считать runtime-проверкой.
- Архивы `kubedesk_0.1.0_<os>_<arch>.tar.gz` и `SHA256SUMS`; внутри только `kubedesk`, `README.txt`, `LICENSE`. SHA256 не заменяет подпись.
- MIT для собственного кода только после проверки происхождения; чужие notices сохраняются. Неясные права или приватные данные блокируют публикацию.
- README/справочник на русском. Без нового UI/backend, произвольных окружений, Windows, Homebrew tap, автообновления, Apple signing/notarization и обещания универсальной поддержки exporter-ов.
- dots переключается только после проверенного релиза; обычная сборка dots не скачивает kubedesk. Чужие файлы/ссылки и основной `dots-tools` не перезаписывать при миграции Kubernetes.
- Не затрагивать dirty `tools/task-tab-groups/`; изменения dots выполнять в изолированном worktree. Не запускать реальный setup/installer против пользовательского HOME при тестировании.

## Review Focus

1. Существующий новый config повреждён, недоступен или является dangling symlink: ошибка, не чтение старого конфига и не смешивание credentials — Task 2.
2. macOS сохраняет alias в `os.Executable()`: watcher должен войти в собственный dispatcher, не отправить внутренние flags в kubectl, и завершить детей при отмене — Task 3.
3. Чужая/сломанная ссылка или старый multifunction `dots-tools` рядом с устанавливаемым бинарником: сохранить чужое и runtime, отклонить небезопасную установку — Tasks 3, 7.
4. Оборванный download, неверный checksum или tar с traversal/link entry: ошибка без замены рабочего бинарника и без записи вне staging — Task 7.
5. Forwarding через старые команды с пробелами, stdin, pipe и SIGINT: сохранить argv/bytes/exit status, не добавить shell и лишний родительский процесс — Task 7.

## Рабочие корни, порядок и решения исполнителя

Это одна миграция с зависимым этапом доставки, не два независимых продукта. Tasks 1–6 относятся к новой репе, Tasks 7–8 — к dots. Порядок последовательный; не удалять старый продукт заранее.

- `SOURCE` — исходный dots snapshot. База разведки: `9a53c2063e6bced60949bbe2c6a8fd6798061009`; дизайн записан коммитом `85d2a58`. Перед копированием сравнить выбранные пути с базой; изменения в продукте согласовать, а не терять.
- `KUBEDESK` — новый соседний каталог `../kubedesk`, только если отсутствует; если уже существует — остановиться и выяснить назначение, не перезаписывать. Новая Git history, не fork всей истории dots.
- `DOTS` — отдельный worktree ветки `extract-kubedesk` от согласованного HEAD, создаётся по skill `using-git-worktrees` при исполнении. Не делать stash/reset пользовательских изменений. Записать абсолютные корни в локальном журнале, не в публичных файлах.
- Пути в Tasks 1–6 относительны к `KUBEDESK`, в Tasks 7–8 — к `DOTS`. Команды выполняются из соответствующего корня. `SOURCE` используется только для разового переноса/сравнения, не в сборке.
- Выбранный способ forwarding: `syscall.Exec`, без PATH-поиска, в `${XDG_DATA_HOME:-$HOME/.local/share}/dots/bin/kubedesk`. Сохранение PID/stdio/environment обеспечивает естественную доставку сигналов.
- Выбранный installer dots: Go package с HTTP/checksum/tar/build-info проверками; явная команда `dots-tools setup kubedesk-install`. Это не новый installer для пользователей отдельного kubedesk: им достаточно release archive.
- Когда существуют оба новых metrics-файла, порядок config → data; затем legacy config → legacy data. Для нового файла без существующих кандидатов выбрать безопасный config, иначе data. Любой существующий небезопасный кандидат блокирует fallback.
- Минимальные CI runners: `ubuntu-latest` и `macos-latest`; записывать фактические `GOOS/GOARCH`. Для прочих архитектур — cross-build и явное указание отсутствия runtime smoke, а не выдуманная проверка.
