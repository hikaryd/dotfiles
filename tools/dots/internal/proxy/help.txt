Pi Proxy — запускает xray-core как локальный HTTP-прокси для Pi
через VLESS-сервер на VPS или через VLESS-подписку.

Зачем:
  - корпоративный VPN продолжает работать для корпоративных ресурсов;
  - Pi ходит через локальный HTTP proxy 127.0.0.1:10810;
  - xray запускается как обычный процесс, а не как системный VPN.

Использование:
  pi-proxy                    # выбрать сервер и запустить xray
  pi-proxy --set-vless         # вставить один vless:// конфиг
  pi-proxy --set-sub           # сохранить URL подписки и обновить серверы
  pi-proxy --update            # обновить список серверов из подписки
  pi-proxy --allow-insecure-sub --update
                                 # аварийно обновить подписку без TLS-проверки сертификата
  pi-proxy --auto              # проверить выход вне РФ и выбрать быстрейший до OpenAI
  pi-proxy --ensure            # проверить кеш (30 мин), при сбое повторить автовыбор
  pi-proxy --list              # показать все серверы
  pi-proxy --status            # проверить процесс и OpenAI через proxy
  pi-proxy --print-env         # вывести export-команды для текущего shell
  pi-proxy --run [args...]     # автовыбор + запуск pi CLI с proxy env
  pi-proxy --stop              # остановить xray

Автовыбор:
  Реальная страна выхода определяется через Cloudflare trace внутри туннеля.
  РФ и неизвестная страна исключаются. OpenAI должен вернуть HTTP 200/401;
  403, 429, 5xx и ошибки TLS не считаются рабочим маршрутом.
  До 4 изолированных xray параллельно, медиана 3 свежих запросов до OpenAI.
  Повторы одной конфигурации проверяются один раз. Кеш — 30 минут;
  при каждом запуске проверяются страна выхода и доступность OpenAI.
  При отсутствии рабочего выхода вне РФ Pi не запускается напрямую.
  Обычный pi запускает --ensure автоматически; --auto обновляет выбор вручную.

Примеры:
  pi-proxy --set-vless
  pi-proxy
  pi-proxy --status
  pi-proxy --allow-insecure-sub --update
  pi-proxy --run
  pi-proxy --run -p "ping"
