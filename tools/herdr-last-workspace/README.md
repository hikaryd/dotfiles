# Herdr last workspace

Нативный Go-помощник для плагина `dots.last-workspace` и хоткея
`Ctrl+A → Shift+L`. Бинарник одноразовый: фонового демона, Python и запуска
CLI Herdr на каждое событие нет. Используется только стандартная библиотека Go.

## Сборка и установка

Из корня `~/dots`, при работающем Herdr:

```sh
./scripts/build-herdr-last-workspace.sh
herdr plugin link "$PWD/config/herdr/plugins/last-workspace" --enabled
dots-last-workspace prime
```

Бинарник устанавливается в `~/.local/bin/dots-last-workspace`; этот каталог
должен быть в `PATH` сервера Herdr. Для сборки нужен Go 1.23 или новее, для
запуска Go не нужен. Скрипт сборки заменяет бинарник атомарно и оставляет
предыдущую версию на месте при ошибке сборки. Сборка и регистрация плагина также
включены в `steps/terminal.yml`.

После изменения исходников повторить сборку. Если изменён манифест плагина,
повторить `herdr plugin link`. Перезапуск сервера не требуется. `prime` нужен
при первоначальной установке: регистрация плагина не запускает startup hook.

## Поведение

- `prime` сверяет сохранённую историю с текущим workspace.
- `focused` обрабатывает `HERDR_PLUGIN_EVENT_JSON`, игнорируя устаревшие
  и повторные события фокуса.
- `toggle` переключает текущий и предыдущий живые workspaces. При отсутствии
  предыдущего workspace ничего не переключает.

Используются запросы `workspace.list` и `workspace.focus` к Unix-сокету из
`HERDR_SOCKET_PATH`. Без него учитываются `HERDR_SESSION` и `XDG_CONFIG_HOME`.
Полный `session.snapshot` не запрашивается.

История хранится в `HERDR_PLUGIN_STATE_DIR`; по умолчанию —
`${XDG_STATE_HOME:-~/.local/state}/herdr/plugins/dots.last-workspace`.
JSON-поля `current`/`previous` и имя файла `sha256(socket_path)[:16].json`
совместимы с прежним Python-плагином. Истории и блокировки разных сессий
изолированы. Запись атомарная, одновременные команды сериализуются через
`flock`. На блокировку и API-вызовы даётся общий таймаут 4 секунды;
ошибки видны в журнале плагина, отвергнутое переключение не сохраняется.

Herdr 0.9.1 опрашивает пустое API-соединение с интервалом 100 мс.
Поэтому запрос сериализуется **до подключения** и отправляется целиком одной
записью. Это уменьшает шанс попасть в ожидание сервера, но не гарантирует
отсутствие задержек под нагрузкой.

## Проверки

```sh
go -C tools/herdr-last-workspace test -race ./...
go -C tools/herdr-last-workspace vet ./...
go -C tools/herdr-last-workspace test -run '^$' -bench BenchmarkPrimeSocket -benchmem
```

Тесты используют собственный Unix-сокет и временные файлы, не изменяя рабочие
сессии Herdr. Покрывают переключение туда-обратно, совместимость старой истории,
запоздалые события, закрытые workspaces, конкурентные вызовы, таймауты и ошибки
сервера. Benchmark измеряет логику с сокетом и блокировкой **без запуска процесса**.

В локальном сравнении 40 запусков `prime` на Apple M4 Pro / macOS:

| Реализация | Медиана | p95 |
|---|---:|---:|
| Python + CLI Herdr | 74,6 мс | 93,4 мс |
| Go + прямой сокет | 6,3 мс | 8,7 мс |

Это время всей команды с запуском процесса. Холодный запуск и нагрузка могут
давать существенно большие пики; это не гарантия задержки хоткея или отрисовки UI.
Собранный с `-s -w` бинарник занимает около 3,1 MiB: он больше исходного скрипта,
но не требует отдельного интерпретатора.
