# Группы вкладок по задачам

Локальное расширение для Brave/Chromium: именует существующие группы вкладок
Kaiten + GitLab по номеру и названию задачи и показывает их состояние на странице
**«Обзор задач»**. Без отдельного сервера и дополнительных зависимостей.

## Установка

1. В `brave://extensions` включить режим разработчика.
2. Нажать **Загрузить распакованное расширение** и выбрать эту папку.
3. Открыть расширение, выбрать нужное окно и нажать **Выбрать**.

Пока окно не выбрано, расширение ничего не меняет. После перезапуска браузера
выберите окно заново. Названия обновляются автоматически; кнопка
**Обновить названия** запускает ручной проход. Хоткей задаётся отдельно
в `brave://extensions/shortcuts`.

Для своего имени отредактируйте поле группы и нажмите **Закрепить 🔒**;
**Снять 🔒** возвращает автоматическое именование. Фиксация хранится в имени группы.

## Обзор задач

После обновления файлов нажмите **↻** у расширения в `brave://extensions`.
Откройте popup расширения → **Открыть обзор задач ↗**. Страницу можно закрепить
или вынести в отдельное окно. Повторное открытие переключает на существующий обзор.
В обзоре выберите **Источник**: окно применяется сразу, без дополнительной кнопки.
Если источник ещё не выбран, вместо пустой таблицы показаны окна с числом групп
и примерами вкладок. После перезагрузки расширения выбор нужно подтвердить заново.
Группы появляются сразу, не дожидаясь ответов API. Счётчик свежих данных показывает
успешность чтения, а не только наличие разрешений. Настройки доступа сворачиваются.

Для команды **Открыть обзор задач, MR и CI** можно назначить хоткей
в `brave://extensions/shortcuts`.

- Одна компактная строка — одна группа выбранного окна, в порядке вкладок и с её
  цветом: **Задача / Kaiten / Merge requests / Ревью / CI**. Количество MR, одобрения
  и результат CI видны без раскрытия. Кнопка **▸** или ячейка MR/ревью/CI показывает
  подробности и ссылки.
- Kaiten: колонка, ответственные участники, блокировка, срок и архивность.
  Если вкладки Kaiten в группе нет, карточка определяется по номеру задачи в
  заголовке MR (`ATS-N` или поддерживаемый семизначный префикс). Для этого
  развёртывания номер задачи — ID карточки: `https://kaiten.x5.ru/space/18571/boards/card/N`.
  Статус читается в фоне, без открытия вкладки. В подробностях отмечен источник
  «Найдена по номеру задачи в MR». Явная ссылка Kaiten имеет приоритет.
- GitLab: сводка всех MR, в подробностях каждый отдельно; draft/open/merged/closed, конфликты, незакрытые
  обсуждения, назначенные ревьюеры и CI.
- **Ревью** читается отдельно через GitLab `/approvals`, а не выводится из CI,
  mergeability или списка назначенных ревьюеров. «✓ Одобрено» требует фактического
  учитываемого одобрения и выполненных правил GitLab. Одобрение автоматического
  аккаунта **@SRV.SAMEDI не учитывается**: ни в числе одобривших, ни для заполнения
  обязательного количества одобрений. Исключение — по точному username без учёта
  регистра, не по отображаемому имени. В подробностях объясняется исключение.
  «Ждёт одобрений» показывает, сколько ещё нужно. Если правил нет и учитываемых
  одобрений нет, это нейтральное «Нет одобрений»:
  GitLab может вернуть `approved: true` и в этом случае. Для нескольких MR показана
  общая сводка; зелёный итог — только когда одобрены все. В подробностях отдельно
  **Одобрили** и **Назначены на ревью**. Ошибка `/approvals` не стирает MR/CI,
  но ревью становится неизвестным, без сохранения прежнего зелёного статуса.
- Наличие обсуждений не выдаётся за запрос изменений; отсутствие pipeline отличается
  от неизвестного состояния CI. MR без pipeline не ухудшает успешный итог других
  pipeline: «✓ Пройден · 1 из 1 · 1 MR без CI». Настоящий `skipped` отмечается
  отдельно; если pipeline нет ни у одного MR, зелёного успеха нет.
- Поиск по номеру, имени, проекту и исполнителю; фильтры внимания/незавершённых/
  готовых/неполных данных. «Готово» требует завершённых карточек Kaiten и отсутствия
  открытых MR. Одного merged MR для этого недостаточно.
- Нажатие на название группы или `Enter` открывает существующую вкладку Kaiten,
  а при её отсутствии — MR или первую вкладку группы. Ссылки на карточки/MR и
  раскрываемый список вкладок позволяют выбрать точное назначение. Клик по ячейке
  Kaiten или ссылке карточки переиспользует уже открытую карточку (в том числе
  в другом окне); только если её нет, создаёт вкладку в группе задачи.
- `/` — поиск, `↑`/`↓` или `j`/`k` — выбор строки, `Escape` в поиске — очистка.

### Статусы и доступ

Без дополнительных разрешений работают список групп, поиск и переходы.
**Включить статусы** запрашивает необязательные разрешения `scripting` и доступ
только к `https://kaiten.x5.ru/*` и `https://scm.x5.ru/*`. **Отключить** отзывает
разрешения и удаляет кэш статусов. Именование групп от этих разрешений не зависит.

Чтение выполняется в изолированном контексте существующих вкладок выбранного окна:
только `GET` с текущей сессией сайта. Если вкладка выгружена, заморожена, загружается
или инъекция недоступна, запрос выполняет service worker расширения с разрешением
на тот же сайт. Так же читается карточка, определённая по номеру задачи в MR,
если вкладки Kaiten нет. Браузер сам прикладывает cookies сессии; расширение не извлекает их,
не читает DOM, не копирует токены и не изменяет карточки/MR. Спящие вкладки не
открываются и не перезагружаются. Если фоновый запрос не авторизован, показана ошибка
входа, а не успешный статус.

Обновление — раз в минуту, только пока страница обзора видима. Изменения групп
обновляют список автоматически; статусы кэшируются на минуту. При выключенном
автообновлении события вкладок обновляют только список, без запросов к сайтам.
Выбор нового окна и кнопка **Обновить** остаются явными запросами статусов.
Кнопка **Обновить**
запускает ручную проверку (защита от повторов — 5 секунд). Одновременно выполняется
не более трёх чтений. Полученные ответы появляются по мере готовности, не ожидая
медленные вкладки. На одно чтение — максимум 20 секунд в service worker, включая
инъекцию и fallback; таймер не зависит от зависшего renderer. Явно замороженные
и выгруженные вкладки читаются фоновым GET без инъекции. Если renderer завис без
соответствующего флага браузера, остаётся таймаут. Пока старая инъекция не завершилась,
повторная не создаётся.
Данные старше двух минут или с ошибкой повторного чтения
помечаются как последние известные; ошибочные/устаревшие ответы не дают «Готово».

Используются Kaiten **`GET /api/cards/:id`** (endpoint веб-клиента данного
развёртывания), GitLab `GET /api/v4/projects/:project/merge_requests/:iid` и
`GET /api/v4/projects/:project/merge_requests/:iid/approvals`.
В 0.2.4 живое чтение подтверждено: 6/6 карточек, включая 3 найденные по MR,
и 11/11 MR без ошибок. В 0.2.5 новый reader проверен на тех же 11 MR:
8 с одобрениями, 3 без одобрений и обязательных правил; ошибок чтения ревью нет.
В 0.2.6 результат уточнён исключением @SRV.SAMEDI: 7 MR с учитываемыми одобрениями,
4 без них. В 5 MR исключено автоодобрение, в одном оно было единственным.
Проверены живые ответы всех 11 MR, ошибок нет.
Прежние `/api/v1/cards/:id` и `/api/latest/cards/:id`
не являются сессионным endpoint этого веб-клиента и больше не запрашиваются.
При ошибках API показывается фактическая причина, а не утверждение, что
пользователь не вошёл в сайт. Автоматического обхода или запроса токена нет.

В **Доступ к статусам → Скопировать диагностику** доступен отчёт для разбора
сбоев: версия, число групп и ресурсов, число свежих ответов, коды ошибок по сайту
и счётчики CI (`success`, `none`, `skipped`, неизвестные/устаревшие и т. п.),
ревью (`approved`, `pending`, `not-required`, `unknown`) и ошибок чтения одобрений.
Названий задач, URL, ID карточек, имён людей и учётных данных в нём нет. Если
браузер запретит буфер обмена, текст можно скопировать из поля под кнопкой.

Источники схем: фактический ответ веб-клиента Kaiten и
[публичная схема карточки](https://developers.kaiten.ru/cards/retrieve-card),
[GitLab merge requests](https://docs.gitlab.com/api/merge_requests/#get-single-mr) и
[GitLab MR approvals](https://docs.gitlab.com/api/merge_request_approvals/#retrieve-approval-state-for-a-merge-request).
Публичная схема Kaiten не используется как доказательство совместимости его
versioned API с браузерной сессией.
В память `storage.session` сохраняются только идентификаторы ресурсов, краткие поля
статуса, ошибки и время проверки; описания, полные ответы и учётные данные не
сохраняются. Кэш переживает остановку MV3 worker, но не перезапуск браузера;
при следующем обзоре удаляются записи вне выбранного окна. История не ведётся.

## Границы

- Автоматическое именование меняет только имя группы: порядок, цвета и свёрнутость
  не трогаются. Выбор окна в обзоре использует тот же выбор, что и popup.
- Чтение обзора не меняет группы. Только явный переход раскрывает нужную группу,
  активирует существующую вкладку и фокусирует её окно. Карточки не дублируются.
- Новая вкладка создаётся для самого обзора либо по явному клику на карточку,
  найденную по MR, если она ещё не открыта. Только новая карточка добавляется в
  группу задачи; существующая карточка из другого окна не перемещается.
- Номер задачи не подменяется номером MR или ID карточки. Конфликты показываются явно;
  при недостатке метаданных хорошее существующее имя сохраняется.
- Источники статусов — URL карточек/MR в группе и номер задачи из метаданных MR.
  Связь `ATS-N → карточка N` специфична для этого развёртывания и подтверждена
  живым чтением. Номер MR и произвольное имя группы не используются как ID Kaiten.
  Отсутствующие MR не разыскиваются по всем проектам.
- Базовые разрешения: `tabs`, `tabGroups`, `storage`; доступ к истории не нужен.
  Правила именования — в `naming.js`; источники обзора — в `overview-model.js` и
  `status-reader.js`. Данные не отправляются третьим сторонам.

## Проверка из корня dots

```sh
npm --prefix tools/task-tab-groups test
npm --prefix tools/task-tab-groups run check
```

Браузерные smoke tests (Brave и Playwright, `BRAVE_BINARY` переопределяет путь):

```sh
uv run --with playwright python tools/task-tab-groups/tests/browser_smoke.py
uv run --with playwright python tools/task-tab-groups/tests/overview_smoke.py
uv run --with playwright python tools/task-tab-groups/tests/overview_regression.py
uv run --with playwright python tools/task-tab-groups/tests/overview_resilience.py
uv run --with playwright python tools/task-tab-groups/tests/overview_background.py
```

Все используют временные профили и локальные фикстуры: рабочие сайты и основной
профиль не затрагиваются. Первые четыре перехватывают HTTP(S)-запросы; background-тест
подменяет DNS двух сайтов локальным HTTPS-сервером и блокирует разрешение остальных
имён, включая запросы service worker. Для временного сертификата нужен `openssl`. Обзор проверяется
без разрешений и с заранее выданными разрешениями в тестовой копии manifest
(только для обхода нативного диалога в headless). Проверяются настоящая MV3-инъекция,
поиск, фильтры, клавиатура, переход без новой вкладки, сохранение цветов/свёрнутости,
ошибка входа с устаревшим кэшем, отсутствие скрытых запросов при выключенном
автообновлении, выбор/переключение источника без второго подтверждения, синхронизация
с popup, сброс фильтра при смене окна, перезапуск браузера и ширины 320–2560 px.
Resilience-тест останавливает renderer карточки через CDP Debugger и проверяет,
что три MR появятся до таймаута карточки; затем проверяет компактность строки
с тремя MR и раскрытие ссылок. `OVERVIEW_SCREENSHOT=/tmp/overview.png`
сохраняет снимок на синтетических данных. Background-тест проверяет реальный GET
из worker с тестовой HttpOnly/Secure/SameSite=Strict cookie, CI `success + none`,
ошибку 401 и сохранение последнего статуса, получение карточки по MR без её
вкладки и открытие по клику без дубликатов. Renderer действительно остановлен CDP,
но флаг `tabs.frozen` подставляется только в тестовой копии: CDP не обновляет этот
флаг Brave. Выгруженная вкладка отдельно покрыта unit-тестом; нативный discard в
headless Brave разрывает Playwright-сессию. Эти тесты не подтверждают доступность API
или сессионную авторизацию на корпоративных экземплярах Kaiten/GitLab.
Дополнительно проверены три состояния ревью, агрегация MR, реальные одобрения
вместо назначений, частичная ошибка API ревью при успешном MR/CI и диагностика.
Отдельные живые проверки 0.2.4–0.2.5 и их границы описаны в [VALIDATION.md](VALIDATION.md).
