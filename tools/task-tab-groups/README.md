# Группы вкладок по задачам

Локальное расширение для Brave/Chromium: именует существующие группы вкладок
Kaiten + GitLab по номеру и названию задачи и показывает их состояние на странице
**«Обзор задач»**. Без отдельного сервера и дополнительных зависимостей.

## Установка

1. В `brave://extensions` включить режим разработчика.
2. Нажать **Загрузить распакованное расширение** и выбрать эту папку.
3. Открыть расширение, выбрать нужное окно и нажать **Выбрать**.

Пока окно не выбрано, расширение ничего не меняет. После перезапуска браузера
выберите окно заново. Названия обновляются автоматически; кнопка
**Обновить названия** запускает ручной проход. Хоткей задаётся отдельно
в `brave://extensions/shortcuts`.

Для своего имени отредактируйте поле группы и нажмите **Закрепить 🔒**;
**Снять 🔒** возвращает автоматическое именование. Фиксация хранится в имени группы.

## Обзор задач

После обновления файлов нажмите **↻** у расширения в `brave://extensions`.
Откройте popup расширения → **Открыть обзор задач ↗**. Страницу можно закрепить
или вынести в отдельное окно. Повторное открытие переключает на существующий обзор.
Для команды **Открыть обзор задач, MR и CI** можно назначить хоткей
в `brave://extensions/shortcuts`.

- Одна строка — одна группа выбранного окна, в порядке вкладок и с её цветом.
- Kaiten: колонка, ответственные участники, блокировка, срок и архивность.
- GitLab: каждый MR отдельно, draft/open/merged/closed, конфликты, незакрытые
  обсуждения, необходимые одобрения (если сообщил API), назначенные ревьюеры и CI.
  Наличие обсуждений не выдаётся за запрос изменений; отсутствие pipeline отличается
  от неизвестного состояния CI.
- Поиск по номеру, имени, проекту и исполнителю; фильтры внимания/незавершённых/
  готовых/неполных данных. «Готово» требует завершённых карточек Kaiten и отсутствия
  открытых MR. Одного merged MR для этого недостаточно.
- Нажатие на название группы или `Enter` открывает существующую вкладку Kaiten,
  а при её отсутствии — MR или первую вкладку группы. Ссылки на карточки/MR и
  раскрываемый список вкладок позволяют выбрать точное назначение.
- `/` — поиск, `↑`/`↓` или `j`/`k` — выбор строки, `Escape` в поиске — очистка.

### Статусы и доступ

Без дополнительных разрешений работают список групп, поиск и переходы.
**Включить статусы** запрашивает необязательные разрешения `scripting` и доступ
только к `https://kaiten.x5.ru/*` и `https://scm.x5.ru/*`. **Отключить** отзывает
разрешения и удаляет кэш статусов. Именование групп от этих разрешений не зависит.

Чтение выполняется в изолированном контексте существующих вкладок выбранного окна:
только `GET` с текущей сессией сайта. Расширение не извлекает cookies, не читает DOM,
не копирует токены и не изменяет карточки/MR. Выгруженные вкладки не пробуждаются
автоматически — их нужно открыть самостоятельно.

Обновление — раз в минуту, только пока страница обзора видима. Изменения групп
обновляют список автоматически; статусы кэшируются на минуту. Кнопка **Обновить**
запускает ручную проверку (защита от повторов — 5 секунд). Одновременно выполняется
не более трёх чтений. Данные старше двух минут или с ошибкой повторного чтения
помечаются как последние известные; ошибочные/устаревшие ответы не дают «Готово».

Используются `GET /api/v1/cards/:id` с ограниченным fallback на документированный
`GET /api/latest/cards/:id`, и GitLab `GET /api/v4/projects/:project/merge_requests/:iid`.
Поддержка сессионного входа зависит от конфигурации корпоративных сайтов:
первое живое подключение нужно проверить после выдачи разрешений. При ошибках
входа/API показывается причина, а не придуманный статус. Если сайт не принимает
сессионный доступ, автоматического обхода или запроса токена нет.

Источники схем: [Kaiten card](https://developers.kaiten.ru/cards/retrieve-card),
[GitLab merge requests](https://docs.gitlab.com/api/merge_requests/#get-single-mr).
В память `storage.session` сохраняются только идентификаторы ресурсов, краткие поля
статуса, ошибки и время проверки; описания, полные ответы и учётные данные не
сохраняются. Кэш переживает остановку MV3 worker, но не перезапуск браузера;
при следующем обзоре удаляются записи вне выбранного окна. История не ведётся.

## Границы

- Автоматическое именование меняет только имя группы: порядок, цвета и свёрнутость
  не трогаются. Выбор окна в обзоре использует тот же выбор, что и popup.
- Сам обзор не меняет группы. Только явный переход раскрывает нужную группу,
  активирует существующую вкладку и фокусирует её окно. Карточки не дублируются.
- Новая вкладка создаётся только для самого обзора, если он ещё не открыт.
- Номер задачи не подменяется номером MR или ID карточки. Конфликты показываются явно;
  при недостатке метаданных хорошее существующее имя сохраняется.
- Источники статусов — URL карточек и MR, реально присутствующих в группе. По номеру
  ATS не угадывается ID Kaiten. Отсутствующие MR не разыскиваются по всем проектам.
- Базовые разрешения: `tabs`, `tabGroups`, `storage`; доступ к истории не нужен.
  Правила именования — в `naming.js`; источники обзора — в `overview-model.js` и
  `status-reader.js`. Данные не отправляются третьим сторонам.

## Проверка из корня dots

```sh
npm --prefix tools/task-tab-groups test
npm --prefix tools/task-tab-groups run check
```

Браузерные smoke tests (Brave и Playwright, `BRAVE_BINARY` переопределяет путь):

```sh
uv run --with playwright python tools/task-tab-groups/tests/browser_smoke.py
uv run --with playwright python tools/task-tab-groups/tests/overview_smoke.py
```

Оба используют временные профили и перехватывают **все** HTTP(S)-ответы локальными
фикстурами: рабочие сайты и основной профиль не затрагиваются. Обзор проверяется
без разрешений и с заранее выданными разрешениями в тестовой копии manifest
(только для обхода нативного диалога в headless). Проверяются настоящая MV3-инъекция,
поиск, фильтры, клавиатура, переход без новой вкладки, сохранение цветов/свёрнутости,
ошибка входа с устаревшим кэшем и узкое окно. `OVERVIEW_SCREENSHOT=/tmp/overview.png`
сохраняет снимок на синтетических данных. Эти тесты не подтверждают доступность API
или сессионную авторизацию на корпоративных экземплярах Kaiten/GitLab.
