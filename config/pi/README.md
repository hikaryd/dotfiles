# Pi Agent

[Pi Coding Agent](https://pi.dev) с личными настройками, темой **Ayu** и статус-баром. Бар показывает модель, уровень размышления, каталог, Git-ветку, TPS, контекст и общее недельное окно Codex.

## Установка

Из корня репозитория:

```sh
./install -c steps/pi.yml
```

Полная установка `./install` тоже включает Pi. Существующий CLI сохраняется без переустановки и обновления. Если его нет, `scripts/pi-install.sh` устанавливает `@earendil-works/pi-coding-agent@1.1.0` через npm в `~/.local` с `--ignore-scripts`; нужны Node.js 22.19+ и npm (`brew install node`). Версия пакета закреплена, транзитивные зависимости npm отдельно не фиксируются. Launcher от официального установщика в `~/.pi/agent/bin/pi` переиспользуется.

Для обновления только конфигов и темы, без установки CLI:

```sh
python3 palette/generate.py --tool pi
python3 scripts/pi-apply.py
```

## Личные настройки

`config/pi/settings.json` хранит переносимые предпочтения из текущей конфигурации:

- `openai/gpt-6.1-sol`, thinking `xhigh`;
- Ayu, скрытые thinking-блоки и индикатор прогресса терминала;
- локальный HTTP-прокси `http://127.0.0.1:10810`;
- отключённую install telemetry;
- `defaultProjectTrust: "always"` — как в текущем конфиге. Это автоматически разрешает проектные ресурсы, в том числе исполняемые расширения; для незнакомых проектов задайте `"ask"` или запускайте `pi --no-approve`.

Установщик рекурсивно применяет поля `settings.json` и `models.json`, связывает только свои тему и расширение. Неописанные в шаблонах настройки, чужие расширения и провайдеры сохраняются. Изменяемые JSON сначала копируются рядом с оригиналами, заменяемые ресурсы — в `~/.pi/agent/backups/`, вне автозагрузки расширений. Путь конфигов можно изменить через `PI_CODING_AGENT_DIR`.

`auth.json`, сессии, `deviceId` и `lastChangelogVersion` не переносятся в репозиторий. Установщик не читает и не меняет авторизацию; локальные идентификаторы и историю сохраняет. На новом компьютере выполните `/login` в Pi.

В активной сессии выполните `/reload` для бара. Тему выбирайте через `/settings` → Theme → `ayu`; новые сессии используют её автоматически. Для обновления окна контекста откройте `/model` и заново выберите `openai/gpt-6.1-sol`, либо перезапустите `pi --continue`.

## Недельная квота

Источник — установленный **CodexBar**:

```sh
codexbar usage --provider codex --source cli --format json --no-credits --no-color
```

Берётся только общее семидневное окно аккаунта Codex; лимиты отдельных моделей и code review не подставляются вместо него. В баре **`Codex 7d`** — оставшийся процент и время сброса. Обновление раз в минуту и после завершения задачи; `/quota` обновляет принудительно.

Это аккаунт, выбранный в Codex CLI, **не гарантированно аккаунт OpenAI в pi**. Текущий OAuth провайдера `openai` в pi не даёт читать endpoint лимитов; отдельная «квота pi» не выдумывается. Если меняете аккаунты, учитывайте источник подписи `Codex 7d`.

При ошибке последнее реальное значение помечается `stale` (или `~` на узком экране); при отсутствии данных — `unavailable`, а не фиктивные 100%. После времени сброса старое значение не используется. В print/JSON/RPC-режимах бар не запускает фоновых процессов. Токены и ответы с данными аккаунта не пишутся на диск.

## TPS

`42.5 tps` — средняя скорость последнего завершённого ответа текущей модели: `usage.output / (durationMs / 1000)`. Включает reasoning-токены и ожидание ответа провайдера, но не время выполнения инструментов. Это средняя скорость запроса, не мгновенная скорость декодирования. Во время генерации сохраняется последнее измерение; при отсутствии токенов/тайминга или смене модели — `— tps`. После `/reload`, восстановления сессии и перехода по дереву значение берётся из текущей ветки истории.

## Контекст

`config/pi/models.json` задаёт `contextWindow: 400000` для `openai/gpt-6.1-sol`. Это локальное окно pi для расчёта заполнения и компактации, не увеличение лимита OpenAI и не максимальная длина ответа. Если upstream не принимает такой контекст, уменьшите override.

## Прокси

Shell-обёртка `pi` поднимает существующий `codex-proxy` и передаёт proxy env только дочернему процессу. Для прямого запуска бинарника в `~/.pi/agent/settings.json` используется `"httpProxy": "http://127.0.0.1:10810"`; Xray должен быть запущен. В pi настройка прокси общая для сетевых запросов, не только OpenAI.

Проверки:

```sh
node --test config/pi/tests/*.test.mjs
python3 -m unittest discover -s scripts/tests -p 'test_pi_*.py'
```
