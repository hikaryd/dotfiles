## Jevgrep: поиск по поведению

Для вопроса о том, как, почему или где реализовано поведение, сначала прочитай глобальный skill `jevgrep` и запусти `jg "<вопрос>" <каталог>`. Для известного файла, точного символа или строки используй прямое чтение и `rg`. При делегировании поиска укажи подагенту `jg` и корень проекта.

В shell-инструментах агента используй `~/dots/scripts/jg`, если нужен настроенный в dots прокси; в интерактивной оболочке `jg` уже обёрнут. Выбирай узкий каталог; перед большим сканированием оцени область через `jg files <каталог>`. Сначала прочитай возвращённые исходники, затем ищи конкретные пробелы. Дождись завершения запущенного поиска, вместо запуска дубликата. Пустой или неполный результат не доказывает отсутствие кода.

Пользователь разрешает удалённую оценку подходящих исходников проекта, над которым просит работать; ограничения раскрытия конкретного проекта имеют приоритет. Jevgrep отправляет исходники выбранному провайдеру: передавай только разрешённую область, сужай её через `--exclude`, сохраняй стандартные фильтры секретов. Учётные данные хранятся вне Git; при их отсутствии попроси пользователя выполнить `jg auth` в терминале, а не передать ключ в чат. При ошибке сообщи причину и продолжай локально через `rg`; `jg doctor` используй для диагностики конкретного сбоя.

Локальный BeatAPI-прокси использует free-first Jev с одной платной резервной попыткой. Она расходует баланс BeatAPI, в том числе при `jg doctor`; условия переключения смотри в `dots-tools proxy beatapi --help`. Fallback уже выполняется внутри прокси: при итоговой ошибке продолжай локально через `rg`, вместо повторного запуска всего поиска.
